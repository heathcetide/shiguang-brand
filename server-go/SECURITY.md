# 安全策略

## 报告安全漏洞

我们非常重视 Shiwei Daily 的安全问题。如果您发现安全漏洞，请按照以下流程报告：

### 请勿公开 Issue

**不要通过 GitHub/GitLab Issue 报告安全漏洞**，这会让漏洞在修复前暴露给公众。

### 报告流程

1. 发送邮件至维护者，主题包含 `[SECURITY]`
2. 在邮件中描述：
   - 漏洞类型（如 SQL 注入、XSS、权限绕过等）
   - 影响范围和严重程度
   - 复现步骤（如有 PoC 请附上）
   - 受影响的版本
3. 维护者会在 **48 小时内** 确认收到
4. 修复方案确定后，会通知您发布时间

### 支持的版本

| 版本 | 支持状态 |
|------|----------|
| 最新 release | ✅ 支持 |
| 前一个 release | ✅ 安全修复 |
| 更早版本 | ❌ 不支持 |

## 安全最佳实践

部署本项目时请注意：

1. **密钥管理**: 不要将 `configs/.env` 或包含密钥的文件提交到 git
2. **JWT Secret**: 生产环境必须修改 `APP_JWT_SECRET`，使用足够强度的随机字符串
3. **数据库密码**: 使用强密码，不要使用默认值
4. **HTTPS**: 生产环境必须通过反向代理（Nginx/Caddy）启用 TLS
5. **CORS**: 根据实际需求配置 CORS 策略，不要在生产环境使用 `*`
6. **依赖更新**: 定期运行 `go mod tidy` 和 `govulncheck` 检查依赖漏洞
