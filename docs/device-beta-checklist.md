# 真机验收与小范围内测清单

> 本页是每个候选版本的真机验收模板，不是最新构建公告。请从[状态导航](status.md)核对目标提交、构建渠道与证据，再填写下方设备、执行人及结果表。自动化、Web 检查或构建成功不能计为真机通过。

2026-10-12 的候选与排期快照保留在 [W42 历史记录](milestone-26w42-progress.md)，不据此判断最新可用包或当前任务状态。所有可分发构建必须使用 HTTPS；HTTP 仅限本机开发。

开发阻断项见 [TODO](../TODO.md)，阶段指标见 [产品路线图](product-roadmap.md)，部署、迁移和恢复步骤见 [运维手册](operations.md)。

## 目标与通过标准

本清单用于验证自动化测试无法覆盖的真实设备行为，包括安装启动、权限、相机、网络切换、键盘、安全区、前后台切换和完整业务链路。

发布候选版本必须同时满足：

- [ ] iPhone 和 Android 各至少一台设备完成核心链路
- [ ] 可安装的候选包完成冷启动和升级安装冒烟测试
- [ ] 已知 P0 全部清零，影响核心闭环、安全或数据正确性的 P1 全部清零
- [ ] staging 只通过 HTTPS 提供服务，候选包不允许明文 HTTP
- [ ] 服务端日志、数据库备份与恢复、管理后台均完成检查
- [ ] 测试账户和测试数据已清理，不包含真实敏感健康数据

## 2. 环境准备

- [ ] 优先连接 staging HTTPS API；临时使用局域网时，手机可以直接访问电脑的 LAN IP 和服务端端口
- [ ] client/.env 的 EXPO_PUBLIC_BACKEND_BASE_URL 不使用手机无法访问的 localhost
- [ ] staging 使用独立数据库、独立 JWT 密钥和非生产 AI 密钥
- [ ] staging 使用持久化 PostgreSQL volume，API 与 worker 的 `DATABASE_DRIVER=postgresql` 且连接同一已迁移数据库
- [ ] 已准备至少一条已审核菜谱、一条待审核投稿和临期库存测试数据
- [ ] 已记录测试开始前的数据库备份，并验证 /api/v1/health
- [ ] 演示用户、社区内容和高互动数据在 staging/production 默认不自动生成
- [ ] iOS 和 Android 均先卸载旧版本，执行一次全新安装
- [ ] 候选包阶段再覆盖一次“保留本地登录状态的升级安装”

本地联调可以在仓库根目录运行：

    pnpm dev

`client/eas.json` 已提供双端内部 preview 与 production profile，iOS bundle identifier 和构建号也已配置。所有可分发构建必须通过 EAS 环境注入 HTTPS `EXPO_PUBLIC_BACKEND_BASE_URL`；缺失或使用 HTTP 会直接失败。HTTP 仅用于本机开发，不能生成或替代候选包。

## 3. 候选提交前的 P0 阻断确认

开始真机功能验收前，先由开发者或审核者确认：

- [ ] 登录邮箱/手机号与公开昵称已经拆分，既有社区、评论和菜谱作者信息已迁移
- [ ] AI、首页和采购页使用同一份用户隔离采购清单
- [ ] 采购清单“一键入库”写入服务端，库存页能从 API 立即读到
- [ ] 首页不存在跳转到 `/recipe-generator` 的断链
- [ ] 小票识别、采购清单、天气、同步和清理缓存不再展示伪造结果或假成功
- [ ] 全新数据库能完成自定义食物投稿、审核和管理统计，`user_custom_foods.status` 字段存在
- [ ] 演示种子数据仅在显式 demo/seed 模式启用
- [ ] AI 数据告知、保留和删除行为与服务端实际存储一致
- [ ] 原生端 Token 使用安全存储，候选包不包含明文 API 地址或 cleartext 放行

## 4. P0 核心链路

以下每一项都要在 iOS 和 Android 上分别勾选。

### 安装与启动

- [ ] iOS / [ ] Android：全新安装后能正常冷启动，无白屏、闪退或无限加载
- [ ] iOS / [ ] Android：启动图、图标、应用名称和状态栏显示正确
- [ ] iOS / [ ] Android：切到后台 30 秒再返回，页面和未提交输入保持合理
- [ ] iOS / [ ] Android：强制结束 App 后重新打开，登录状态和数据恢复正确

### Android 应用内更新（#219）

首次先手动安装包含更新原生模块的候选；旧包无法仅靠 JS 增加此能力。准备同包名、同渠道、同签名且更高构建号的第二个候选，按[发布与撤下步骤](w41-account-recovery-and-app-updates.md#发布与撤下)配置稳定 HTTPS 下载源。

- [ ] 启动与手动入口均发现正确新版；相同/旧版本、其他包名或渠道不混发；稍后再说不阻断使用
- [ ] 下载进度、取消/重试、断网和空间不足提示正确；大小、哈希、包名、渠道或签名不符时拒绝安装
- [ ] 来源授权关闭时进入系统设置，返回后再次点击安装；系统取消不显示升级成功
- [ ] 同签名覆盖安装成功，新原生版本正确，登录、已有记录和本地数据保留
- [ ] 服务不可用不误报最新版；下载后撤下/替代推荐包，安装前再次核对并拒绝旧推荐

### 注册、登录与健康目标

- [ ] iOS / [ ] Android：弱密码、错误密码和重复注册都有明确提示
- [ ] iOS / [ ] Android：新用户可以注册、登录并完成健康档案
- [ ] iOS / [ ] Android：用户可以设置公开昵称，社区和菜谱中不会显示登录邮箱或手机号
- [ ] iOS / [ ] Android：身高、体重、日期等非法或极端值会被拦截
- [ ] iOS / [ ] Android：退出登录后无法继续访问原用户的私有数据

### 忘记密码（#221）

使用隔离环境及授权测试号码，先确认账号已有验证绑定的手机号；当前不支持邮箱恢复。实现边界见[账号恢复记录](w41-account-recovery-and-app-updates.md#221-自助找回密码)。

- [ ] iOS / [ ] Android：登录页进入忘记密码，收到真实短信并完成验证与重设，新密码可登录、旧密码及旧会话失效
- [ ] iOS / [ ] Android：错误/过期验证码、重复提交、断网、提供商失败和限流均给出可恢复提示，不假报发送成功
- [ ] iOS / [ ] Android：无可用绑定手机的账号获得明确限制和人工核验途径；停用账号不能借恢复重新登录

### 库存与临期食材

- [ ] iOS / [ ] Android：手动添加食材后立即出现在库存列表
- [ ] iOS / [ ] Android：编辑、删除、标记用完和恢复操作结果正确
- [ ] iOS / [ ] Android：过期、3 天内临期、正常和已用完状态显示正确
- [ ] iOS / [ ] Android：拒绝相机/相册权限时有说明，允许后可以继续操作
- [ ] iOS / [ ] Android：AI 扫描结果必须经过确认才写入库存
- [ ] iOS / [ ] Android：扫描中断或失败后能够安全重试，不产生重复食材
- [ ] iOS / [ ] Android：AI 添加的采购项会出现在正式采购页，重新启动后仍存在
- [ ] iOS / [ ] Android：采购清单一键入库后，服务端库存立即可见且不会重复入库

### 菜谱、烹饪与饮食记录

- [ ] iOS / [ ] Android：推荐结果能区分已有、缺少和临期食材
- [ ] iOS / [ ] Android：待审核投稿不会出现在正式推荐中
- [ ] iOS / [ ] Android：菜谱详情能够进入烹饪模式并完成全部步骤
- [ ] iOS / [ ] Android：完成烹饪时可以选择是否扣减库存
- [ ] iOS / [ ] Android：完成烹饪后保存制作份量与待吃份量，仅实际食用的部分生成饮食记录
- [ ] iOS / [ ] Android：完成动作中断后可安全重试，不会出现原料扣减与制作批次分离、重复扣减或把待吃份量记为摄入
- [ ] iOS / [ ] Android：首页、饮食页和健康页的今日营养数据一致
- [ ] iOS / [ ] Android：营养数据缺失时显示未知，不使用虚假的默认值

### 隐私与账户

- [ ] iOS / [ ] Android：AI 健康建议附近持续显示“非医疗诊断”说明
- [ ] iOS / [ ] Android：首次发送健康上下文给 AI 前有清晰告知，并可查看处理方、存储范围、保留期限和删除方式
- [ ] iOS / [ ] Android：隐私政策、用户协议和账号注销入口可访问
- [ ] iOS / [ ] Android：错误密码无法删除账号
- [ ] iOS / [ ] Android：删除账号后 Token 失效，重新登录失败，私有数据被删除

## 5. 安全与数据隔离

- [ ] 用户 A 新建库存、饮食记录和健康数据
- [ ] 用户 B 无法读取、编辑或删除用户 A 的数据
- [ ] 普通用户无法进入管理员接口或执行审核操作
- [ ] 连续登录失败会触发限流，等待后可恢复
- [ ] 重复快速点击提交不会生成重复记录
- [ ] 图片、音频类型或体积不合规时被拒绝，并有用户可理解的提示
- [ ] 社区、评论、菜谱和管理页面均不会泄露用户登录标识、完整 AI 对话或不必要的健康信息

## 6. 网络与异常恢复

- [ ] 启动前关闭网络，App 不闪退并显示可恢复的错误或空状态
- [ ] 请求过程中从 Wi-Fi 切换到蜂窝网络，恢复后可以重试
- [ ] 请求过程中锁屏或切到后台，返回后不会重复提交
- [ ] 模拟服务端不可用、超时和 401，提示与登录跳转符合预期
- [ ] AI 请求失败不会写入半成品数据，也不会阻塞非 AI 核心功能
- [ ] 外部服务超时或服务端重启后，扫描任务会失败或恢复，不会永久停在处理中
- [ ] 网络恢复后下拉刷新或重新进入页面可以获得最新数据

## 7. 设备交互与视觉

- [ ] 小屏设备上没有横向溢出、按钮遮挡或无法滚动的内容
- [ ] 刘海、灵动岛、底部手势区和 Android 状态栏不会遮挡操作
- [ ] 键盘弹出时当前输入框、提交按钮和错误提示仍然可见
- [ ] 应用保持当前固定亮色主题时，系统深色/浅色切换不会造成局部混色或低对比度
- [ ] 系统字体放大一级后核心流程仍可完成
- [ ] 旋转设备时保持预期的竖屏方向，不出现布局错位
- [ ] 长库存、长消息和长社区列表滚动流畅，无明显卡顿
- [ ] 图片加载中、加载失败和重新加载状态显示正确

## 8. 服务端、管理后台与运维

- [ ] 管理后台可以登录、修改初始密码并审核菜谱投稿
- [ ] 核心请求日志包含 requestId，错误可通过请求 ID 定位
- [ ] AI 用量记录包含模型、耗时、Token、估算费用和失败原因
- [ ] CORS、HTTPS、JWT 和管理员初始密码使用 staging 配置
- [ ] 在空目录启动一次服务端，验证迁移、注册、自定义食物投稿/审核和核心统计
- [ ] 执行一次数据库备份，并在隔离目录完成恢复演练
- [ ] 恢复后验证健康检查、登录、库存读取和管理统计
- [ ] 发布候选提交再次通过以下命令：

    pnpm -w lint:all
    pnpm -w test:all

    pnpm -w build:server
    pnpm -w build:admin
    pnpm -w audit:prod

## 9. 缺陷等级与发布判定

| 等级 | 定义 | 处理要求 |
| --- | --- | --- |
| P0 | 闪退、核心链路中断、数据丢失、越权或隐私泄露 | 立即停止发布 |
| P1 | 核心功能明显错误，但存在临时绕过方式 | 修复并双端回归后发布 |
| P2 | 文案、间距或低频体验问题 | 记录负责人和计划，可评估后发布 |

缺陷记录至少包含：

- 标题与等级
- 设备、系统、App 版本、Git 提交和后端环境
- 前置条件、复现步骤、实际结果和预期结果
- 截图或录屏，以及相关 requestId
- 修复提交、iOS 回归结果和 Android 回归结果

## 10. 小范围内测

真机验收通过后，邀请 5～10 位用户连续使用 7 天：

- [ ] 记录注册、首次有效库存录入、菜谱匹配、烹饪、扣减和饮食记录的匿名漏斗
- [ ] 10 人中至少 8 人完成激活，6 人录入 3 种以上真实食材
- [ ] 10 人中至少 4 人完成一次完整闭环，3 人在第 7 天回访或再次完成核心动作
- [ ] 收集用户无法继续操作的页面、原因和截图
- [ ] 汇总最常见的三个困惑点和三个最有价值的功能诉求
- [ ] 内测结束后优先修复阻塞问题，再决定是否开发临期食材每日提醒

人数少于 10 时记录绝对人数和个体路径，不换算百分比。内测期间避免采集不必要的健康数据或完整 AI 文本；分析数据使用匿名用户标识，并提供退出内测和删除数据的方式。
