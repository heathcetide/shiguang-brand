## 启用、回退与流式边界

- `AI_MAIN_ASSISTANT_ENABLED=false`：新任务使用兼容路由路径。默认开启主助手；不修改模型默认值。任务创建时冻结开关，现存待批准任务不重新生成动作。
- `AI_REPLY_STREAM_ENABLED=true`：新任务在已经过产物/动作检查的最终汇总阶段，持久化仅解码 `reply` 的正文片段。默认关闭，先验证提供商流式能力再启用。自动重试在已开始流式输出的阶段禁用，防止拼接两次生成。
- 原生与 Web 共用已有 GET 游标轮询（1.5 秒），保留断网恢复，不增加原生 SSE 依赖。重复片段去重，重试从新的 `reply_started` 重置，完成后使用权威最终回复。
- 主助手的一次调用直接答复目前在完整结构化结果和候选检查后显示，**不是 token 级实时展示**。任务步骤不计作“首个有效回复”。
- 无数据库 schema 迁移；保留旧角色模型设置。旧格式的待输入 checkpoint 在 resume 时迁移到独立澄清节点；仍需在部署前使用旧版本真实 checkpoint 验证迁移。

## 性能采样

`scripts/benchmark-ai-conversation.mjs` 自动运行 A1–A3 的只读文本样本，输出每次 runId、状态、模型调用数、重试数、可用的单次模型首 token、首次可查询正文时间、端到端时间，按用例汇总样本数、成功率及成功样本 P50/P95。缺失指标为 null，不写成零。250ms 采样轮询带来测量误差；App 的真实首屏正文另行录制测量。

在已授权的隔离测试部署中设置以下环境变量后运行（token 不写入仓库或报告）：

```sh
AI_BENCHMARK_URL=https://your-test-origin.example
AI_BENCHMARK_TOKEN=<test-account-token>
AI_BENCHMARK_LABEL=<commit-provider-model-thinking>
AI_BENCHMARK_SAMPLES=20
AI_BENCHMARK_OUTPUT=/tmp/ai-benchmark.json
node scripts/benchmark-ai-conversation.mjs
```

以上为变量说明，执行时需通过安全环境注入或 export。默认 5 次/用例仅用于流程冒烟；20 次/用例已超过默认 15 分钟 30 次的限流，需在测试部署事先安排采样间隔或显式测试限额，不修改生产限流。超时不会自动取消服务端任务，报告保留 runId 供核对。

同部署、同账号数据、同模型、同思考策略分别比较 `AI_MAIN_ASSISTANT_ENABLED=false/true`；旧部署缺少模型事件时从已有 usage 日志补齐，不能把缺失次数当零。模型更换实验另列一组。基线完成后再确定数值目标和默认模型。
