## 当前关键路径结论

### #62 持续音频仍需实现和供应商决策

静态调用链：`realtimeVoice` 的 `POST /sessions/:sessionId/audio-chunks` 接收完整 base64 音频片段，调用 `transcribeAudio`，后者以 multipart 文件请求 `/audio/transcriptions` 并等待完整 JSON。下行 SSE 和文字增量不构成持续供应商音频流。

因此当前无法将 #62 归类为“只差真机验收”。用户当前无可用语音服务；先在资源对话确定可用供应商/模型及预算，再核对持续上行、增量转写、取消与重连官方能力，实施单一适配。不自行开通付费服务，也不把按轮模式标成实时能力完成。

### #187 数据证据没有自动升级

本轮重新运行 `python3 datasets/base-data/source_coverage.py`，报告保存在忽略目录 `artifacts/quality/w44-email-recovery/data-audit.json`。它审计的是冻结参考包 `system-data-2026-09-15.2`，不是线上食谱计数；人工审核、正式 v1 发布和目标环境验证仍未完成。缺依据的条目继续保持不可自动执行。本次冻结包计数：389 个配方方法，279 个缺份数、272 个缺食材身份或精确用量、290 个缺设备；369 个带来源 URL 和声明许可。

## 邮箱恢复交付契约

- `POST /api/v1/auth/email-verification/send`：已登录，当前密码复核，向账号已有注册邮箱发送验证码；不提供任意换绑邮箱入口。
- `POST /api/v1/auth/email-verification/verify`：已登录，验证 challengeId/code，绑定用户、当前邮箱和会话版本。
- `POST /api/v1/auth/email-recovery/send`：标准化 email；合规地址使用同样发送流程，收码不表明账号存在或可恢复。
- `POST /api/v1/auth/email-recovery/verify`：验证后仅对已验证邮箱、启用账号签发短时恢复凭据。
- `POST /api/v1/auth/password-recovery/reset`：沿用旧接口；可选 `channel: "email"`，省略继续为短信。凭据跨通道不可用。
- 验证码和恢复凭据各 5 分钟，验证码最多 5 次尝试；发送按 IP/全局/账号或邮箱限流，邮箱重发至少 60 秒。
- 新增 SQLite 90 / PostgreSQL 0031；历史 `email_verified_at` 为 NULL。管理员改邮箱清除验证状态并吊销旧会话；验证/重设事务重检状态。
- 无密码账号先用既有手机复核设置密码；失联且无已验证通道者走人工核验。未实现任意邮箱首绑/换绑 UI。
- SMTP 使用 Nodemailer，465 为直接 TLS，其他端口要求 STARTTLS并校验证书；配置见 `server/.env.example` 和 `deploy/server.env.example`。缺配置明确 503，不记录验证码、密码、令牌或 SMTP 错误原文。
- 本地测试注入邮件发送器，不发送真实邮件；真实 SMTP/短信送达必须另验。
