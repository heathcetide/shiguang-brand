## #222 反馈闭环

- 用户提交反馈后进入同一反馈详情；可分页查看自己的记录、状态时间线和补充回复。
- 管理端可按状态/分类筛选、公开回复并更新状态、保存仅管理员可见的内部备注。
- 公开回复在同一事务写入站内通知与管理员审计，通知预览不包含用户反馈正文；通知可跳回对应反馈。
- 提交/回复有账号限定幂等键、内容冲突检测、版本竞争保护。非本人读取返回 404，非管理员管理操作返回 403，已关闭反馈不接受用户追加。
- SQLite v83 与 PostgreSQL 0025 对等迁移，旧 open 状态转为 received。用户注销级联清理反馈消息；公开诊断字段仅白名单版本、平台和页面。
- SQLite 接口验证隔离、重放、冲突、内部备注隐藏、分页、通知失败回滚与删除；PostgreSQL 独立空库验证迁移、并发事务、备份恢复及 HTTP 运行时通过。
- 本地浏览器使用一次性测试账号完成：提交 → 管理员要求补充 → 站内通知跳转 → 用户在原反馈内补充，状态变为处理中。

## #220 烹饪计时

- 删除语音偏好 effect 对计时的重置；显示 tick 仅重新读取时钟，倒计时以开始时间和剩余基数计算，暂停不耗时。
- 按账号及队列任务/菜谱保存，页面重进、重启可恢复。切换步骤保留现有计时，重置显式使用当前步骤建议时长。
- 原生倒计时使用固定标识的本地通知，暂停、加时、模式切换、制作完成更新/取消；退出账号取消该账号计时通知。异步权限返回后再次验证账号代次，避免退出后建立通知。
- 正计时不发到时通知。通知拒绝、网页限制和系统强制停止限制有明确说明；页面不另行震动/朗读，避免与系统提醒重复。
- 规则/Hook 测试验证时钟恢复、暂停、重进、任务隔离、通知次数、退出与权限竞争；浏览器验证朗读切换后计时继续，刷新后恢复实际剩余时间，无控制台错误。
- **仍需 Android/iOS 真机验收**锁屏、后台、系统通知权限与系统强制停止。没有据 Web 验证声称原生提醒已验收。

## #179 提醒操作与业务归因

- 客户端接通现有 snooze/not_cooking_today/not_helpful 事务接口，先展示影响再要求明确确认；失败重试复用同一幂等键。
- 账号/令牌切换丢弃旧请求结果，迟到的菜谱标题读取不会覆盖已处理状态。
- 组件回归覆盖确认前不写、响应丢失后的相同身份重试、成功显示已处理。
- 库存卡片逐批核对当前数量、版本和所属账号，明确确认整批已使用/已丢弃；部分使用继续走库存管理。结果、单批关闭、提醒动作、通知状态、归因及计划维护事件在同一事务写入，失败整体回滚。更正使用/丢弃/未知后同步修正归因。
- 安排菜谱需要再次确认，幂等加入烹饪队列；入队不写饮食或库存，也不计为已开始。实际进入 cooking 状态后才记录开始归因，原先已在烹饪的条目不追溯计入。
- SQLite/PostgreSQL 共享回归覆盖跨账号/错误食材/非关联菜谱拒绝、版本和重复载荷冲突、并发重放、写入失败回滚、纠错与真实开始归因。
- 管理端显示近 30 天候选、策略阻止、投递、处理、实际开始、确认使用/丢弃及比例；明确关联不等于因果，推送接受不等于送达，未处理不等于忽略。展示默认关闭状态和停用方式。
- 浏览器隔离数据完成库存确认，以及安排→队列→实际开始；管理端对应显示 2 条已处理、1 次安排、1 次实际开始和 1 次使用。客户端与管理端无控制台错误。
- 修复确认页被应用 GET 缓存返回旧库存的问题：确认读取显式绕过缓存，结果写入使库存及 insights 缓存失效，并补回归。
- **外部验收仍待完成**真实 Expo 推送/设备与生产规模吞吐；主动推送默认开关保持关闭。
