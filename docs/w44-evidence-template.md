# W44 验收证据模板

复制后填写；默认未执行，空白或待确认均不代表通过。步骤来源见[执行单](w44-acceptance-runbook.md)。原验收条目需逐项映射，不能只附一个“测试通过”截图。

## 候选和环境

- 证据 ID / Issue / 原验收条目 / 执行单 ID：待填
- 源码完整 SHA / 后端版本 / 数据迁移版本：待填
- 数据包版本 / manifest 与包 SHA-256 / 审核报告：待填或明确不适用原因
- 平台 / 包名 / 渠道 / 版本 / 构建号 / 签名证书摘要 / 包 SHA-256：待填
- 旧候选身份（升级场景）/ 新候选身份：待填
- HTTPS 环境标识 / 设备型号 / OS / 浏览器：待填
- 证据类别：local、ci、staging、real-provider、device、human-review 中选择，可多选但逐文件注明
- 执行人 / 复核人 / 开始与结束时间（ISO8601，含 +08:00）：待填
- 授权测试账号代号 / 测试数据版本 / 权限及网络条件：待填
- 资源配置状态：待填；不记录密钥、验证码、密码、完整 Token 或未脱敏个人数据

## 步骤与结果

| 步骤 | 前置与操作 | 预期（执行前填写） | 实际 | 状态 | 证据文件/URL与SHA256 |
|---|---|---|---|---|---|
| 1 | 待填 | 待填 | 未执行 | not_run | 待填 |

状态仅使用 not_run / blocked / failed / passed。截图与日志应能对应到同一操作ID、候选和时间；日志包含业务状态前后变化，设备结果需要系统实际行为证据。CI日志不能放在真机证据栏充数。

## 阻断、复验与收口

- 资源缺口 / 责任人 / 预计提供时间：待确认；没有承诺日期时写“待确认”
- 缺陷 Issue / 复现 / 严重性 / 修复 PR / 新候选 SHA：待填
- 受影响场景及核心烟测复验：待填，引用新证据 ID；旧证据保留，不覆盖
- 跨日、恢复计时或延迟原始记录：待填或明确不适用
- 已覆盖原验收条目 / 尚未覆盖条目：逐项列出
- 执行结论：未验收
- 复核结论 / 人员 / 时间 / 原因：待填
- 是否满足 Issue 全部原标准：否（证据复核后才能改）

## #106 专用补充

- 故障开始、最近可恢复业务时间、恢复文件完成、全部业务检查通过时间：分别记录
- RPO = 故障时间 − 最新可恢复业务时间；完整 RTO = 业务恢复通过 − 故障开始
- 目标：RPO≤24h、RTO≤2h；备份存储/异地副本/保留策略/校验值/恢复目标/失败保护及运维交接人：待填

## #187 人工决定补充

- 记录 kind/id、line_id（如适用）、原记录 SHA、缺项、原文及来源版本：待填
- 许可/身份/营养/配方/厨具/实做证据及摘要：待填
- 审核角色及人员、时间、适用范围、通过/退回/补证、理由、复核人：待填
- 字段确认与整道配方执行批准分别记录；缺一类必需审核仍不可自动执行

## P0 汇总兼容

`deploy/p0-report.mjs` 仅接受 passed/failed/blocked；本模板的 not_run 对应未提交的检查项，不能转成passed。复制下面条目时必须替换全部待填值并附真实证据，否则不用于通过判断：

```json
{
  "candidateSha": "待填40位SHA",
  "owner": "待认领",
  "stagingUrl": "https://staging.example.invalid",
  "checks": []
}
```

检查 ID 以 `deploy/p0-report.mjs` 的 requiredChecks 为准，完整保留 #105/#106/#107 所有项；文件路径相对输入目录，证据存放受控目录。工具的 readyForReview 只是汇总状态，最终关闭仍需人工复核原验收要求。
