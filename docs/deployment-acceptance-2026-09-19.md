## AI 真实提供商结果与限制

沿用原配置 `deepseek-ai/DeepSeek-V4-Flash`，没有更换模型或修改思考策略。使用临时账号，只读请求没有产生业务动作。

1. 初次上线后，寒暄返回非 JSON，库存工具往返触及内部 `recursionLimit=6`。两项明确代码问题已修复并补回归。
2. 修复后隔离环境的寒暄、烹饪问答、库存概括均完成，单样本耗时约 23.5s、8.7s、5.6s。
3. 修复后的目标 HTTPS 环境同三项均完成，单样本约 2.6s、6.7s、3.1s。每项仅一个样本，不具备稳定 P50/P95 或改前改后性能结论。
4. 显式营养工具查询仍出现模型只返回目标、没有答复/后续任务的情况，服务端按规则失败，没有虚构结果或业务写入。因此不能将主助手真实工具能力或 #224–#230 标记为完整验收。

5. 隔离兼容路径的寒暄和营养请求均完成（3 次模型调用，约 18.3s / 9.2s），但仅凭最终答复与完成状态不能证明真实工具已经执行，不能作为工具能力验收通过的依据。
6. 发布配置将 API 和三个 worker 的 `AI_MAIN_ASSISTANT_ENABLED=false`，恢复兼容路由。新主助手路径暂不启用；其余对话历史、任务卡与审批改动保留。重新启用前须完成真实工具执行证据、能力矩阵及相同模型的性能对照。

JSON 模式依据[SiliconFlow 官方说明](https://docs.siliconflow.cn/docs/userguide/guides/json-mode)；合法 JSON 不等于满足业务契约，服务端继续执行 Zod 和业务安全校验。
