# W44 剩余验收执行单

更新：2026-11-01（上海时间）。本文件是待执行步骤，不是通过记录。配合 [原验收矩阵](w44-acceptance-matrix.md)、[证据模板](w44-evidence-template.md) 和各 Issue 原验收标准使用，发现遗漏时补充执行，不以本表缩减原范围。

## 执行前与顺序

1. 用户提供入口/配置名称、授权账号、签名和设备；密钥仅进环境或密钥管理。资源缺失填写 blocked、责任人待认领和预计提供时间待确认，不伪造执行日期。
2. Codex 核对 main CI、数据库迁移版本、环境隔离和回滚点。部署前备份。先完成 #187 数据审核与 #62 必需实现，再冻结服务端/Android/iOS 同一 SHA。环境演练可提前准备，最终验收必须重跑最终候选。
3. 每个实际构建先按仓库规则预留新 snapshot/buildNumber，失败不复用；安装名“食光烙记”。记录旧/新包包名、签名证书摘要、构建号、包 SHA-256、下载源及后端 SHA。没有签名不生成假候选。
4. 按环境→数据与媒体→安装更新→账号/录音→真实业务→双端全矩阵顺序执行。共享证据只在同 SHA/环境和相同场景内复用，各 Issue 单独判定。
5. 任何阻断失败：记录原候选、复现与关联 PR；修复后新候选重跑受影响步骤及核心烟测。旧候选通过不自动迁移。跨日步骤必须真实跨日，不能改系统时间冒充。
